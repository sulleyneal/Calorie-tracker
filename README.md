# 🍓 Morsel

A delightful calorie tracker. Tell it what you ate the way you'd text a friend —
*"had a cappuccino and an almond croissant"* — and Morsel keeps the journal,
the math, and the pictures.

- **Chat to log.** Free-text meal logging with quantities ("two eggs and toast").
- **Accurate nutrition.** Calories and macros come from the
  [USDA FoodData Central](https://fdc.nal.usda.gov/) API, with a built-in
  USDA-derived database of ~120 common foods as offline fallback.
- **Gorgeous food photos.** Every logged item gets a soft-studio food photo
  generated by **nano banana** (`gemini-2.5-flash-image`) — white ceramic
  dishware on a blush gradient. Without a key, foods get cute illustrated
  plates instead.
- **A journal worth scrolling.** Day-by-day feed with daily totals, protein /
  carbs / fat chips, an animated progress bar toward your goal, and a little
  celebration when you land on target.
- **Thoughtful touches.** Log the same thing twice and Morsel asks whether it
  was a second helping or the same plate.

## Quick start

```bash
npm install
cp .env.example .env   # add your keys (optional but recommended)
npm start              # → http://localhost:3000
```

### No server handy?

```bash
npm run demo   # builds dist/morsel.html
```

`dist/morsel.html` is the whole app in one file — open it in any browser
(works great on a phone). It runs the offline parser, the built-in USDA-derived
food database, and illustrated plates entirely client-side, persisting your
journal to localStorage. Nano banana photos and live USDA lookups need the
real server with keys.

## Keys

| Variable | What it unlocks | Where to get it |
| --- | --- | --- |
| `GEMINI_API_KEY` | nano banana food photos + smarter free-text parsing (`gemini-2.5-flash`) | [aistudio.google.com/apikey](https://aistudio.google.com/apikey) |
| `USDA_API_KEY` | higher rate limits on USDA FoodData Central (falls back to `DEMO_KEY`) | [fdc.nal.usda.gov/api-key-signup](https://fdc.nal.usda.gov/api-key-signup) |

No keys at all? Morsel still works: the local parser recognizes ~120 foods
with USDA-derived portions and macros, and every entry gets an illustrated
plate.

## How a meal gets logged

1. **Parse** — `gemini-2.5-flash` turns "had a latte and a bagel" into
   structured items (name, portion, grams). Offline, a longest-match parser
   over the built-in food database does the same.
2. **Nutrition** — each item is looked up in USDA FoodData Central
   (FNDDS / SR Legacy / Foundation data), scaled to the portion's grams, and
   sanity-checked against the parser's estimate.
3. **Photo** — nano banana renders the item on white ceramic against a blush
   gradient; images are cached on disk in `data/images/`.
4. **Journal** — the entry lands in `data/db.json` and in your scrollable
   day-by-day feed.

## Stack

Node + Express, zero front-end dependencies — one HTML file, one stylesheet,
one script. Data lives in a JSON file; images on disk. `npm start` is the
whole deployment story.
